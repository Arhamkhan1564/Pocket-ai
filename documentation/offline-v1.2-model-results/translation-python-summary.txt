Processing and actual runtime
- ONNX Runtime1.20.0 CPUExecutionProvider, SentencePiece0.2.1.
- Official IndicTransToolkit1.1.1 IndicProcessor, reviewed processor.pyx, with
  sacremoses / IndicNLP helpers and inference=True. Transformers4.49 utilities
  are installed for toolkit imports; its model backends are absent and unused.
- Fresh process: source encoder, first decoder, then cached decoder are opened
  sequentially. An earlier heavyweight graph is closed before the next opens.
  Short synthetic encoder outputs and first-step attention caches are retained.
- Input English is normalized/tokenized using the official processor and prefixed
  with two literal language tokens. Source SentencePiece piece STRINGS are mapped
  through dict.SRC.json, not SentencePiece internal integer IDs. Append EOS2.
- IDs: BOS0, PAD1, EOS2, UNK3, eng_Latn4, pan_Guru46, urd_Arab68. Decoder starts2.
- Source dictionary32322, target dictionary122672. Generated token strings from
  dict.TGT.json are joined, ▁ replaced with spaces, then processor postprocessed.
- Urdu model output is already Arabic script. Guru output is unified Devanagari
  and requires official hi->pa transliteration and Indic detokenization.
- 18 layers, eight heads, head dimension64, hidden512; first decoder has73 outputs
  (logits+72 caches), cached graph has74 inputs including input IDs and source mask.
  The cached graph returns full encoder cross-caches, not Marian's empty outputs.
- Graph contracts: session-contracts.json. Exact source/output IDs and raw versus
  processed text for all eight cases: greedy-results.json. Code: run_indic.py.

Decision and limits
This is a materially better candidate than the failed Marian model: all six short
medical-text fixtures visibly preserve the selected number/unit/drug/prohibition
checks. Eight cases are not a translation-quality benchmark or clinical validation.
No fluent-speaker acceptance or actual 2GB ARMv7 device run was performed. Broader
texts, names, identifiers, dates, decimals, units, negation, domain terms, and low
memory still need meaningful validation. No direct Shahmukhi target exists in this
checkpoint. A separately labeled Punjabi Gurmukhi->Shahmukhi transliteration stage
would operate on genuine Punjabi output; it must not substitute Urdu for Punjabi.
Do not claim the prototype completes every language/script or permits clinical use.

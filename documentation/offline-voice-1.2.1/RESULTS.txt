Interpretation and limits
English outputs retained much of the sentence but included contraction/spelling substitutions, and Javanese became Japanese in the second clip.
Urdu stayed in Arabic script but had many substitutions/omissions; basic WER was59.1% and60.0% on these two references.
The second Urdu reference contains چھے (six); that word is absent in the output. Quantity fidelity is not established.
Both Punjabi outputs were Latin romanization/mixed English despite Gurmukhi references and explicit pa selection.
Punjabi cross-script WER100–110.3% is not a meaningful fluency estimate; script mismatch alone is a concrete limitation.
None of these selected references contains decimal digit strings, so digit-quantity preservation was not tested.
This is an exploratory six-clip read-speech check, not a representative FLEURS benchmark. No human listening or fluent-speaker review was performed.
Basic metrics use Unicode NFKC+casefold, punctuation→space, whitespace collapse, retain combining/vowel marks; WER uses whitespace tokens and CER excludes spaces.
That normalization is not an official FLEURS score recipe. Urdu spelling, diacritics and spacing can inflate errors.
Host latency10.84–17.77s and sampled RSS193.6–199.7MB are observations, not predictions for a2GB ARMv7 phone.
Tap-to-talk review/confirmation remains necessary; these observations cannot support a reliable Urdu/Punjabi voice claim.

Reproduction
1. Fetch the pinned dataset row metadata listed in voice-results.json, refresh its public audio URL, and verify source audio SHA256 before use.
2. Convert with:ffmpeg -nostdin -hide_banner -loglevel error -i SOURCE.wav -ac 1 -ar 16000 -c:a pcm_s16le PCM.wav
3. Verify derived audio SHA256 and bundled model digest. Rebuild the canonical JNI target on a host, or validate the recorded host library/source hashes.
4. Compile the scratch NativeBridge.java listing in voice-harness-source.txt; invoke with LIBRARY MODEL LANGUAGE PCM_WAV RESULT_JSON, two threads are hardcoded. Use: java -Xms16m -Xmx128m -cp CLASSES com.pocketai.engine.NativeBridge LIBRARY MODEL LANGUAGE PCM_WAV RESULT_JSON.
5. Compare raw outputs; host floating-point/runtime changes can affect greedy decoding. Do not reuse these metrics as phone or language-acceptance results.
